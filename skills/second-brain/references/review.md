# Plan and review

## Plan

Recall relevant active projects, commitments, and constraints before suggesting actions. If storage is unavailable, plan from supplied context and disclose that limitation. Propose concrete next actions, dependencies, and tradeoffs. Distinguish user-established commitments from recommendations. Ask about capacity only when it materially affects the plan; never invent free time or deadlines.

Keep the plan in conversation until instructed to save it or create tasks. Saving a plan does not schedule reminders or send messages.

## Review

For a weekly or requested-period review:

1. Establish the period from the request and available locale/timezone. Ask if date boundaries materially matter and are unknown.
2. Inspect accessible Inbox items, active projects, relevant tasks, areas, recent resources, and archive candidates. State incomplete coverage.
3. Report progress with evidence, stalled projects, unresolved decisions, and actions lacking a clear next step. Age alone does not prove abandonment or completion.
4. Suggest Inbox destinations, priorities, next actions, and archive candidates with reasons.
5. Apply only explicitly requested changes. Broad review authorization is read-only; “apply these three moves” authorizes those three moves without another confirmation.
6. If asked to save the review, search for the same period before creating a new record and update the existing one where appropriate.

Default response: period and scope, progress, decisions needed, recommended next actions, and proposed changes. Review is on demand. No background job or automatic weekly reminder is included in V1.
